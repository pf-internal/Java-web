チャプター1：Servletは「司令塔」

Servlet は、Webアプリの中で受け取る→判断→渡す→返すを担当する Java クラスです。

データの旅（Servlet の立ち位置）

画面（フォーム）
    ↓  HTTPリクエスト（POST）
【Servlet ← 今日はここ】
    ↓  getParameter で値を受け取る
    ↓  DAO に処理を依頼
    ↓  DB（MySQL）
    ↑  結果を受け取る
    ↓  setAttribute で JSP に渡す
    ↓  forward で JSP へ移動
画面（JSP）← ブラウザに返る

カバ先生：Servlet は画面を自分では描かないのがポイントです。Servlet は表示しない、JSP が表示する。役割を分けることで、それぞれをシンプルに保てます。

チャプター2：doGet / doPost の基本型

Servlet クラスは HttpServlet を継承し、GETとPOSTを別々のメソッドで受け取ります。

@WebServlet("/items")
public class ItemServlet extends HttpServlet {

	// GET リクエスト（一覧表示など）
	@Override
	protected void doGet(HttpServletRequest request, HttpServletResponse response)
			throws ServletException, IOException {

		// ここに GET の処理を書く
	}

	// POST リクエスト（登録・更新など）
	@Override
	protected void doPost(HttpServletRequest request, HttpServletResponse response)
			throws ServletException, IOException {

		// ここに POST の処理を書く
	}
}
キーワード 役割
@WebServlet("/items") このクラスが /items という URL に対応することを宣言する
HttpServletRequest request ブラウザから来た情報（フォームの値など）を受け取る箱
HttpServletResponse response ブラウザへ返す情報を設定する箱
doGet GETリクエスト時に Tomcat から呼ばれるメソッド
doPost POSTリクエスト時に Tomcat から呼ばれるメソッド

カバ先生：フォームの method="post" → doPost、GET リンク → doGet が対応します。Tomcat がメソッドを判断して自動で振り分けてくれます。私たちは中身を書くだけです。

チャプター3：黄金フロー①「受け取る→変換→DAOへ」

フォームから送られた値を取り出し、Java の型に変換して DAO へ渡す流れです。

@Override
protected void doPost(HttpServletRequest request, HttpServletResponse response)
		throws ServletException, IOException {

	// ① フォームの値を受け取る（すべて String で来る）
	String itemName = request.getParameter("itemName");
	String priceStr = request.getParameter("price");

	// ② 型変換（String → int）
	int price = Integer.parseInt(priceStr);

	// ③ DTO（Bean）に詰める
	ItemDto dto = new ItemDto();
	dto.setItemName(itemName);
	dto.setPrice(price);

	// ④ DAOへ渡して DB に登録
	ItemDao dao = new ItemDao();
	dao.insert(dto);
}
ステップ コード 注意点
① 受け取る request.getParameter("itemName") 引数はフォームの name 属性と完全一致させる
② 型変換 Integer.parseInt(priceStr) getParameter の戻り値は必ず String。数値が必要なら変換する
③ DTO に詰める dto.setItemName(itemName) DTO は「データを運ぶ箱」。setter で値を詰める
④ DAO へ渡す dao.insert(dto) DB 操作は DAO の仕事。Servlet は「頼む」だけ

カバ先生：「getParameter の引数とフォームの name 属性は完全に一致させてください。ここが食い違うと null が返ってきて、次の parseInt で例外が起きます。」

チャプター4：黄金フロー②「結果をJSPに渡す」

DAO から受け取った結果を JSP に渡して画面を表示させる流れです。

@Override
protected void doGet(HttpServletRequest request, HttpServletResponse response)
		throws ServletException, IOException {

	// ① DAOから一覧を取得
	ItemDao dao = new ItemDao();
	List<ItemDto> itemList = dao.findAll();

	// ② JSP に渡すために request に保存
	request.setAttribute("items", itemList);

	// ③ JSP に処理を移す（forward）
	RequestDispatcher dispatcher =
			request.getRequestDispatcher("/WEB-INF/jsp/itemList.jsp");
	dispatcher.forward(request, response);
}
ステップ コード 注意点
① DAOから取得 dao.findAll() Unit03で作ったDAOをそのまま使える
② JSPへ預ける request.setAttribute("items", itemList) キー名 "items" でJSP側から取り出せる
③ JSPへ移動 dispatcher.forward(request, response) forwardはサーバ内の移動。URLは変わらない

カバ先生：setAttribute("items", ...) と JSP 側の ${items} は同じキー文字列でつながっています。このキー名はプロジェクト内で統一してください。食い違うと JSP 側で null になります。

チャプター5：データの通り道マップ

今日学んだフローを「名前」で追うと次のようになります。フォームの name 属性から JSP の表示まで、同じキー名がどこで使われるかを意識してください。

【フォーム（HTML）】
  name="itemName"  ←→  name="price"

          ↓ POSTリクエスト

【Servlet の doPost】
  getParameter("itemName")  ←→  getParameter("price")
          ↓ 型変換・DTO に詰める
  dao.insert(dto)  → DB

【Servlet の doGet】
  dao.findAll()  ← DB
  setAttribute("items", itemList)  ← キー名："items"
  forward("/WEB-INF/jsp/itemList.jsp")

          ↓ forward

【JSP（itemList.jsp）】
  ${items}  または  getAttribute("items")  ← 同じキー名："items"

カバ先生：「この図の矢印とキー名を自分で描けるようになることが、今日のゴールです。」

まとめ

  • Servlet は「司令塔」。画面を描かず、受け取り・判断・渡し・返しに専念する
  • doGet は GET リクエスト（一覧表示など）、doPost は POST リクエスト（登録・更新）に対応する
  • getParameter の引数はフォームの name 属性と完全一致させる
  • getParameter の戻り値は必ず String。数値が必要なら Integer.parseInt で変換する
  • setAttribute(キー, 値) → forward で JSP にデータを渡す。キー名は JSP 側と一致させる
  • DAOはUnit03〜04で作ったものを再利用。Servletは「頼む」だけ
