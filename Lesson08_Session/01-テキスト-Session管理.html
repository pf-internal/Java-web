チャプター1：CookieとSessionは「IDと台帳」

図解で仕組みを押さえましょう。

【1回目アクセス】
  ブラウザ ─── HTTPリクエスト ──────────────────→ Tomcat
                                                    ↓
                                             SessionIDを発行
                                             台帳に「userName=ユウタ」を記録
  ブラウザ ←── HTTPレスポンス（Set-Cookie: JSESSIONID=abc123）── Tomcat
  （ブラウザがIDを保存）

【2回目アクセス】
  ブラウザ ─── HTTPリクエスト（Cookie: JSESSIONID=abc123）───→ Tomcat
                                                    ↓
                                             IDで台帳を引く
                                             「userName=ユウタ」を取り出せる
種類 誰が持つ 何を持つ 寿命
Cookie ブラウザ SessionID（番号札） ブラウザを閉じるまで（デフォルト）
Session サーバ（Tomcat） 実際のデータ（台帳） 一定時間操作なし or invalidate() まで

カバ先生：イメージはレストランの番号札です。お客さん（ブラウザ）が番号札（Cookie）を持ち、お店（サーバ）が番号で注文の台帳（Session）を管理します。データはサーバ側に置き、ブラウザには番号だけ渡すのがポイントです。

チャプター2：HttpSession の基本操作

Servlet から Session を操作するコードの型です。

Session に値を保存する 

// Session を取得（なければ新規作成）
HttpSession session = request.getSession();

// Session に値を保存
session.setAttribute("loginUser", "ユウタ");

Session から値を取り出す 

HttpSession session = request.getSession();

// Session から値を取り出す（キャストが必要）
String loginUser = (String) session.getAttribute("loginUser");

Session を破棄する（ログアウト） 

HttpSession session = request.getSession(false); // なければ null を返す
if (session != null) {
	session.invalidate(); // Session を破棄（ログアウト相当）
}

チャプター3：request と session の使い分け

スコープ 寿命 使いどき 操作
request 1回の往復のみ 一覧データ、エラーメッセージなど
1回表示すれば消えていいもの		 request.setAttribute
request.getAttribute
session ブラウザ単位で継続 ログイン情報、カートの中身など
複数ページをまたいで持ち越すもの		 session.setAttribute
session.getAttribute

カバ先生：「判断の基準は簡単です。『次のページでも使うか？』→ Yes なら session、No なら request です。session に何でも入れると、古いデータが残ってバグの原因になります。」

まとめ

  • HTTP はステートレス ── 1回のリクエストが終わるとサーバは相手を忘れる
  • Cookie：ブラウザが持つ SessionID（番号札）。データそのものは持たない
  • Session：サーバが持つ台帳。SessionID をキーに実際のデータを保管する
  • request.getSession() で Session を取得し、setAttribute / getAttribute で操作する
  • 次ページに持ち越す → session ／ 1回だけ使う → request

お題：「CookieとSessionの連携」をホワイトボードに描いて説明してください。
