ミッション3：HelloServletクラスの穴埋め

次のコードは「ブラウザから /hello にアクセスすると "Hello Servlet" と表示する」最小Servletです。（ A 〜 F ） に入るコードを答えてください。

（ A ）("/hello")
public class HelloServlet extends （ B ） {

	@Override
	protected void （ C ）(HttpServletRequest request, HttpServletResponse response)
			throws ServletException, IOException {

		response.setContentType("text/plain; charset=UTF-8");
		（ D ） out = response.（ E ）();
		out.（ F ）("Hello Servlet");
	}
}
記号 自分の解答 ヒント
A URLマッピングを指定するアノテーション
B Servletの親クラス（継承元）
C GETリクエストを受け取るメソッド名
D 文字を出力するためのクラス名
E レスポンスから出力ストリームを取得するメソッド
F 1行出力するメソッド（改行付き）
ヒント①（クラス名のみ）
  • B は HttpServlet です
  • D は PrintWriter です
ヒント②（アノテーションとメソッド名）
  • A は @WebServlet です
  • C は doGet です
  • E は getWriter、F は println です
解答例

【解説・確認用】

@WebServlet("/hello")                          // A
public class HelloServlet extends HttpServlet { // B

	@Override
	protected void doGet(HttpServletRequest request, HttpServletResponse response) // C
			throws ServletException, IOException {

		response.setContentType("text/plain; charset=UTF-8");
		PrintWriter out = response.getWriter(); // D, E
		out.println("Hello Servlet");           // F
	}
}

解答例 
① Tomcat
② webapps

【WEB-INFが外から見えない理由】
Tomcatの仕様として、WEB-INF フォルダへのブラウザからの直接アクセスを
拒否するよう設計されているため。
JSP などの重要ファイルをWEB-INFに置くことで、
Servlet（Controller）を必ず経由させる設計ができる。
